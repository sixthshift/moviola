scrolly

The scrollytelling framework. You write the DOM, scrolly runs the state machine, effects live in your CSS.

scroll ↓

A story is just HTML.

One <figure> stays pinned. These <section class="step"> blocks scroll past it. No build step, no config — one script tag, one stylesheet.

Steps get state classes.

As each step crosses the trigger line it becomes .is-active; the others are .is-past or .is-future. The dimming on this very column is those classes at work.

The graphic follows along.

Tag any element in the figure with data-show="step-id" and it fades in while that step is active. Crossfades are the default; everything is plain CSS you can override.

Progress streams as a CSS variable.

--step-progress runs 0 → 1 through the active step, and --story-progress through the whole story. That bar is pure CSS — no callbacks, no JavaScript.

Any CSS can react to any step.

The root carries data-active-step, so a one-line selector restyles anything on the page. Scroll up and down — the accent color everywhere is doing exactly that.

And there's an API when you need one.

D3 or anything else can listen to stepenter / stepexit / progress events. If you've used scrollama, you already know it.

Resize the window under 720px — the story collapses to an overlay automatically. That's the whole library: a document model, a state machine, and your CSS.
